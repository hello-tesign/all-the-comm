# 국문 PC 전역 모션 최종 UI 검증

확인일: 2026-10-12. 대상: `http://127.0.0.1:4173`, 통합 빌드 준비 후 실행.

**결과: 413개 검사 통과, 사이트 검사 실패 0, 브라우저 JavaScript 오류 0, 문의/쓰기 요청 시도 0.**

- Chromium / Firefox / WebKit 각각 137개 검사와 공통 오류·쓰기 차단 검사 2개.
- 국문 PC 1440×1000: 홈, ABOUT, PROCESS, TEAM, WORKS, CONTACT, PRIVACY, 소적두 CASE. 총 24개 페이지 실행 기록.
- 영문·모바일은 전용 모션 제외 여부와 원래 프로세스 요소 복원만 최소 확인했다. 전체 영문/모바일 디자인 검수는 이번 범위가 아니다.
- 스크린샷 27장: 각 브라우저의 8페이지 상단 및 동작이 끝난 PROCESS 2단계 화면.

## 확인한 동작

원본 SSR의 h1/h2 텍스트, 공식 메뉴 5개와 별도 상담 CTA, 가로 넘침, 두 모션 모듈 활성화, 전역 읽기 선 1개 및 실제 스크롤 진행을 검사했다. TEAM/서비스는 탭 클릭·방향키·Home/End 선택과 연결된 단일 패널을 확인했다. 홈의 3개 프로젝트에도 포트폴리오 모션이 활성화됐다.

PROCESS는 원문 4단계의 스크롤 활성화, 단계 링크, sticky 장면, 원문 보존을 확인했다. 실행 중 동작 축소 설정을 켜면 추가 내비게이션·진행선이 제거되고 원래 article 안으로 4개 art가 복원됐다. 다시 끄면 장면과 진행선이 중복 없이 한 번만 생성됐다.

CONTACT는 합성 이름·회사·연락처·문의 내용을 입력하고 스크롤 후 값과 복수 서비스 선택이 유지되는지만 확인했다. 제출 버튼은 누르지 않았다. 브라우저 경계에서 GET/HEAD/OPTIONS 이외의 요청은 차단했다. CASE의 lazy 이미지는 각 이미지까지 스크롤 후 완료를 기다려 decode했다.

## 실행 및 증거

- 테스트: `tests/isos.cjs` (`node --check` 통과).
- 통합 결과: `results.json`.
- 최초 Chromium 실행 증거: `chromium-initial-with-sandbox-startup-error.json`.
- Firefox/WebKit 실행 증거: `firefox-webkit-results.json`.

최초 샌드박스 실행에서 Chromium의 137개 검사는 통과했으나, Firefox의 페이지를 만들기 전에 도구 환경의 `_page` undefined 오류가 발생했다. 이 초기 파일을 보존했다. 이후 승인된 로컬 GET 전용 실행으로 Firefox와 WebKit을 완료했다. 통합 결과에는 성공한 Chromium 페이지 검사와 최종 Firefox/WebKit 검사만 합쳤으며 환경 오류 경위를 `execution`에 명시했다. 사이트 실패를 성공으로 바꾼 항목은 없다.

PROCESS 캡처는 CSS 전환이 종료된 뒤 3장만 다시 촬영했다. 소스 변경이나 불필요한 전체 테스트 재실행은 없었다. 이 검증은 로컬 프론트엔드 모션/읽기/선택 동작의 증거이며, 실서비스 배포·외부 이메일·문의 저장 API를 새로 검증했다는 의미가 아니다.
