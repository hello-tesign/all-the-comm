# 실제 참조 화면과 편집 기준

2026-10-13. https://freefrontend.com/ 를 독립 Playwright Chromium 1440×1000에서 확인했다. HTTP 200. 초기 샌드박스 원격 접근 제한 후, 읽기 전용 명령의 네트워크 권한으로 재확인했다. 로그인·제출·코드 복사 없음.

## 참조에서 확인한 정돈 원리

- 이미지가 모두 실측 334×208.75px, **16:10** 비율이다. 여러 색의 시안이 있어도 같은 크기와 시작선에 담겨 안정적으로 보인다.
- 4열에서 이미지, 작은 분류, 제목, 설명, 하단 정보의 위치가 반복된다. 제목은 17px/600, 섹션 제목은 24px/700으로 역할이 구별된다.
- 페이지 배경은 `#fafafa`, 본문은 거의 검정이다. 큰 배경색 전환 없이 이미지가 각 항목의 색을 담당한다.
- 카드 본문 자체는 6–7줄로 적지 않다. 이번 회사 사이트에 적용할 핵심은 **규격과 정렬의 일관성**이며, 설명 분량은 의뢰 기업이 빨리 판단할 수 있도록 더 줄이는 편이 좋다.
- 원본 16:9 이미지가 16:10 영역에 표시된다. 우리 웹 캡처에는 문자·내비게이션이 있으므로 원본 전체를 `contain`으로 보존하는 방식이 적합하다.

증거: `freefrontend-desktop-top.png`, `freefrontend-desktop-feed.png`, `freefrontend-observations.json`.

## 현재 ABOUT · TEAM · CONTACT의 편집 방향

현재 통합 빌드와 검수 이미지를 기준으로 한 제안이다. 사이트 구조는 유지한다.

| 항목 | 현재 시각 부담 | 통합 기준 |
|---|---|---|
| 이미지 외곽 | ABOUT 웹 캡처·TEAM 세로 책·CONTACT 2열 캡처의 프레임과 배경이 다름 | 웹 화면은 16:10, 세로 출판물은 4:3 프레임. 같은 행에는 같은 규격. 원본은 contain, 중앙 정렬, 동일한 24px 안쪽 여백 |
| 이미지 크기 | 책 전체 높이 600px, 웹 화면은 원비율 높이여서 설명과 균형이 달라짐 | 외곽 프레임이 크기를 결정하고 내부 이미지는 원비율. 작은 글은 사례 상세에서 확대해 읽게 연결 |
| 캡션 | 프로젝트명·업무·제작자 프로젝트·산출물이 문단과 캡션에 반복 | 캡션 1행은 ‘프로젝트명 · 산출물’, 2행만 상태/출처 12px. 성격 표기는 이 위치에 한 번 |
| 제목 | 영어 라벨, 큰 감성 제목, 역할 제목이 연속 등장 | 섹션 H2가 메시지를 담당. 사례 H3는 프로젝트와 작업을 구체적으로 적고 28–32px, 최대 2줄 |
| 설명 | ABOUT 두 문단+산출물, TEAM 소개+역할3줄+산출물, CONTACT 설명+범위가 모두 비슷한 뜻을 반복 | 사례마다 핵심 문단 1개(약 70–110자), 실제 산출물 1줄, 상세 링크 1개. TEAM은 역할 간 연결 2개만 남김 |
| 배경 | 종이·연한 녹색·베이지 및 캡처 내부의 배경이 중첩 | 페이지 바탕은 기존 paper 한 가지. 이미지 받침은 동일한 옅은 중립색. 짙은 ink는 헤더·푸터·핵심 회사 설명 등 소수 영역에 유지 |
| 본문 폭 | 넓은 문단과 좁은 역할 행이 번갈아 등장 | 설명 열 최대 560px, 16px/1.6. 역할·준비자료는 16px/1.6. 산출물은 14px/1.6, 캡션은 12px/1.5 |

## 적용 가능한 CSS 규칙

수정 제안이며 이번 검토에서는 소스를 변경하지 않았다.

- 콘텐츠 최대 폭 1280px, 열 간격 64px(태블릿 48px), 섹션 96px/모바일 64px 유지.
- 공통 이미지 프레임: `display:grid; place-items:center; aspect-ratio:16/10; padding:24px; border-radius:12px; overflow:hidden;`.
- 원본 이미지: `width:100%; height:100%; min-height:0; object-fit:contain; object-position:center;`로 맞춤. 기존 이미지별 고정 높이는 프레임 내부에서 해제.
- 세로 책 프레임만 `aspect-ratio:4/3`. 모바일은 동일 규칙과 16px 패딩. 필요한 세부는 클릭해 상세에서 읽는다.
- 이미지 뒤로 별도 그림자·장식 테두리를 겹치지 않는다. 캡처 안에 이미 UI가 있는 경우 외곽은 단순한 중립 면 하나로 충분하다.
- 캡션은 16px 위 간격, 항상 왼쪽 정렬. ABOUT의 좌우 분산 캡션과 TEAM의 줄바꿈 규칙을 같은 방식으로 합친다.
- 요약 문장을 줄이는 편집이 먼저다. `line-clamp`로 잘린 문장이나 숨긴 산출물을 늘리면 의미의 중복이 남는다.
- 모션은 프레임의 600ms 입장 한 번으로 통일한다. 제목·문단·역할 행을 각각 따로 움직여 읽는 시작점이 계속 바뀌지 않게 한다.

## 사례별 문안 축약 예시

- TEAM / 세일즈 리허설: ‘340쪽의 전문 원고를 8부·33장으로 구성하고, 본문·도해·실습 양식으로 편집했습니다.’ + `원고 구성·저술 / 내지·도해 편집`.
- TEAM / Kings: ‘브랜드와 메뉴 소개부터 운영 정보, 가맹 상담까지 이어지는 웹을 제작했습니다.’ + `메뉴 정보·카피 / 웹 UI·개발`.
- CONTACT / 먹거리사전: ‘정보가 흩어져 있다면, 월별 품목과 산지를 연결한 이 작업처럼 담당자가 찾고 판단하는 순서부터 정리합니다.’
- CONTACT / 소적두: ‘고객의 이용 목적이 다르다면, 일반 소비자와 사업자가 필요한 상품을 따로 찾도록 탐색을 나눌 수 있습니다.’

각 사례의 제작자 프로젝트·MVP·목업 표기는 캡션에 유지한다. 회사의 수주·운영 성과로 바꿔 소개하지 않는다.
