- 근거: `assets/projects.json`의 실제 공개 API 14개 사례, `assets/cover-metadata.json`의 원본 치수, `assets/image-inventory.json`의 실제 표시 치수, `assets/*-image-area.png`와 추가 캡처.

- 이번 검토는 완성도와 전달력에 대한 편집 판단이다. 유료 수주·성과·상용 서비스 운영을 새로 입증한 검토가 아니다.

## 결론

대표 사례는 **종해문화진흥원·SoulReset·세일즈 리허설**이 적합하다. 기관 웹, 여행 서비스 웹, 한 권의 책이라는 서로 다른 결과물이 명료하다. Kings는 메뉴 정보 화면을 우선 보조컷으로 사용한다. EzyLens의 제품 화면은 시각적으로 정돈됐지만 시제품이라는 단계는 유지한다.

책의 기존 표지는 인물·투명 인체·아이콘·문장이 겹친 이미지여서 현재 요구한 정갈한 이미지 편집과 어울리지 않는다. 대표 이미지는 실제 PDF의 **파트 시작면**으로 바꾸고 원래 표지는 상세 갤러리에 보존한다. 기존 자료만 사용하며 새 목업이나 합성 이미지를 만들 필요가 없다.

## 혼잡 요인 5개

1. **첫 작품의 과도한 크기.** `home-featured.png`에서 첫 종해 사례가 화면 대부분을 채운다. 동일 섹션의 다른 작품과 비교하기 어렵고 회사 페이지 안에 기관 홈페이지 하나가 들어온 느낌이 강하다. 첫 카드만 큰 예외를 없애고 같은 크기의 프레임으로 맞추는 것이 우선이다.
2. **원본 비율이 카드 크기를 결정한다.** 16:10 웹 화면, 1352×2000 책, 1200×1200 포스터, 1440×1558 업무 화면이 섞여 있다. 목록은 같은 16:10 외부 프레임으로 맞추고 원본은 contain으로 보존한다. 책과 포스터의 여백은 의도된 여백으로 취급한다. 큰 원본 감상은 상세에서 맡는다.
3. **화면 안의 글과 바깥 설명이 중복된다.** ABOUT의 753px 정도 웹 캡처 안에 헤더·타이틀·문장이 모두 들어 있고 바로 옆에 긴 제목과 본문이 다시 붙는다. 그림처럼 보아야 할 캡처와 읽어야 할 카피가 경쟁한다. 바깥 메타는 작품명·제작 분야/단계·짧은 설명으로 통일한다.
4. **완성물과 작업 도구의 서열이 같다.** 책·여행 웹 옆에 MVP 알림판, 시연용 원고 에디터, 내부 검수 화면, 자체 안내 시안이 같은 대표작처럼 보인다. 사례는 보존하되 첫 선택은 완료된 결과물에 주고 작업 도구는 기능 사례와 PROCESS의 증거로 배치한다.
5. **같은 전체 화면이 여러 페이지에서 반복된다.** 종해와 SoulReset은 홈·ABOUT·WORKS에, 도구 UI는 홈·서비스·PROCESS·상세에 재등장한다. 같은 프로젝트를 쓰더라도 ‘첫인상/실제 구성/작업 방식’ 중 페이지가 맡은 질문 하나만 설명해야 한다. 한 이미지 옆에서 문제·방향·제작·결과를 반복 설명하지 않는다.

## 페이지별 배분

- **HOME:** hero의 3개 탭 구조는 유지하되 브랜드 웹=Kings 메뉴, UI/UX=EzyLens, 개발=먹거리사전 지도로 한 이미지당 한 주제만 보여준다. 대표 작품 3개는 종해·SoulReset·책으로 제한한다.
- **ABOUT:** 현재 종해·SoulReset의 서로 다른 사업 설명은 근거가 있다. 같은 전체 화면을 보조 이미지로 유지하되 회사 소개보다 길어진 프로젝트 설명을 줄인다. 두 이미지의 외부 프레임과 메타 높이를 통일한다.
- **TEAM:** 책 본문 지면은 저술·편집 역할을 설명하는 데 적합하다. Kings 메뉴 화면도 콘텐츠와 웹 제작의 분업을 보여준다. 역할별 표와 앞뒤 설명이 같은 말을 반복하지 않도록 축약한다.
- **PROCESS:** Radar→원고 편집→책 도해→내부 검수의 화면은 실제 작업 형태를 설명하는 증거다. 다만 서로 다른 프로젝트의 작업 화면임을 유지하고 하나의 고객 프로젝트 진행 사진처럼 만들지 않는다. 긴 캡처를 장식으로 크게 늘리는 것보다 단계와 관련된 한 기능을 설명한다.
- **CONTACT:** 지도와 커머스 화면은 의뢰 유형을 구체화한다. 이미지 2개는 같은 규격으로 두고 본문은 의뢰할 수 있는 범위를 짧게 설명한다. 폼보다 더 무거운 별도 포트폴리오 섹션이 되지 않게 한다.
- **WORKS:** 14개 사례는 보존한다. 모든 목록 이미지를 같은 16:10 틀에 넣고 이미지 위에 긴 문장을 올리지 않는다. 작품명·분류/제작 상태·요약 한 문장으로 정리한다. 클릭 후 상세에서 원본 비율과 갤러리를 충분히 보여준다.

## 이번에 반영한 소스 범위

부모 에이전트의 추가 위임으로 `src/data/portfolio.mjs`, `portfolio-diverse.mjs`, `portfolio-expansion.mjs`의 13개 사례를 편집했다. 자사 사례는 부모 에이전트 담당이다.

- 제목: 긴 슬로건을 덜고 작품명으로 통일.
- 요약: 실제 만든 것 한 문장.
- 문제/전략/제작/결과: 중복을 줄여 각 1~2문장. 결과의 두 번째 문단에 있던 상태·출처·성과 한계는 원문 그대로 보존.
- 원본 갤러리 파일·alt, EN 필드, 기관/서비스/분류/범위/공개 상태/연도/출처 기록은 보존.
- 홈 대표 source 플래그: 종해·SoulReset·책.
- 책 대표 source: 파트 시작면. 원래 표지는 상세 갤러리 첫 번째 `표지`로 추가.
- `copy-check.json`: 13개 사례, 허용 필드 내 85개 변경 검증 통과. 모든 상태/출처 문단과 기존 갤러리 원본 보존 확인.
- 빌드·API 등록·영문 변경은 하지 않았다. 이 문서의 화면 증거는 편집 전 상태이며 최종 통합 화면 검수를 대체하지 않는다.
