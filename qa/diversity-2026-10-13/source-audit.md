# 국문 업종 다양성: 구현 전 감사

확인일: 2026-10-13. 읽기 전용 소스·공개 HTTP 응답 기준. 기존 사용자 IAB 탭에 접근하거나 새로고침하지 않았다. `before/baseline.json`과 6개 HTML에 변경 전 근거를 보존했다.

## 반복이 발생하는 위치

다음 수치는 숨겨진 탭을 포함한 HTML 이미지 태그 수다. 화면에 동시에 보이는 수나 클릭 후 API로 추가되는 포트폴리오 수와는 다르다.

| 경로 | 소적두 이미지 태그 | 발생 위치 |
| --- | ---: | --- |
| 홈 | 9 | 히어로 첫 장면, 전략·콘텐츠·매체·인플루언서 예시, 프로세스 1~3단계, 회사 소개 연결 이미지 |
| ABOUT | 1 | 회사 소개 제조 현장 사진 |
| PROCESS | 3 | 분석·전략·실행의 대표 이미지 |
| TEAM | 8 | 전략, 콘텐츠, 디자인, 영상 3프레임, 매체, 인플루언서 |
| WORKS | 7 | 전략, 콘텐츠, 영상 3프레임, 매체, 인플루언서 |
| CONTACT | 0 | 관련 없음 |

`src/evidence-content.mjs`의 `photo`, `commerce`, `gift` 3개 경로가 `evidenceHero`, `examples`, `sample`, `evidenceAbout`, `evidenceHomeAbout`, `evidenceChapter`, `evidenceProcessPreview`에서 재사용된다. WORKS·홈 서비스·TEAM은 `evidenceVisual()`을 공유하므로 한 예시를 바꾸면 여러 화면이 함께 바뀐다. TEAM 콘텐츠와 디자인은 모두 `content` 예시를 호출한다. 병원 예시는 별도지만 보도자료도 가상 단팥빵 브랜드여서 이름을 지우는 것만으로 식품 편중을 해결할 수 없다.

## 대표 사례와 관리자 데이터

확인 시점의 공개 `/api/projects`는 6개이며 순서는 소적두, SoulReset, Review Atelier, TESIGN Radar, Tesign OS, 자사 리뉴얼이다. `featured=true`는 소적두·SoulReset·자사 리뉴얼 3개다.

`src/app.js`는 API 순서를 유지한 채 홈에서 `featured`만 거른다. 공통 `visibleCount=6`이므로 대표 지정이 4개 이상이면 홈에 4~6개가 표시된다. 홈에 정확히 3개를 유지하려면 홈에만 명시적 상한을 두고 WORKS의 6개 단위 표시와 분리해야 한다.

`src/data/portfolio.mjs`를 수정해도 이미 저장된 관리자의 대표 선택은 바뀌지 않는다. `scripts/import-portfolio.mjs`는 기존 슬러그를 유지하며 `--refresh-copy`도 summary/problem/strategy/execution/result 5개 본문만 바꾼다. 매번 소스 배열 순으로 전체 사례를 재정렬하므로 관리자에서 바꾼 순서를 이후 덮어쓸 수 있다.

관리자 변경은 상세 GET의 전체 객체를 보존해 PUT에 전달하고 `featured` 등 필요한 값만 바꾸는 방식이 안전하다. PUT은 부분 수정이 아니라 문자열·배열·공개 상태 등을 다시 구성한다. `/api/admin/projects/reorder`는 비공개 사례를 포함한 전체 프로젝트 ID를 중복 없이 한 번씩 받아 순서를 0부터 부여한다. 이번 감사에서는 로그인·PUT·POST를 실행하지 않았다.

## 수정 기준과 QA 범위

- 소적두의 상품·제조·선물·커머스 이미지는 WORKS의 단일 포트폴리오 카드와 해당 상세에서만 사용한다.
- 이름만 바꾸거나 같은 식품 소재로 가상 브랜드를 늘리지 않는다. 의료·여행·교육·생활제품·기업/IT 등 다른 고객 과제가 드러나는 출력으로 나눈다.
- 서비스는 매체나 업무의 이름이다. 예시는 그 업무로 만드는 구체적인 결과물이어야 하며, 사진만 다른 상태를 업종 다양성으로 집계하지 않는다.
- 자체 예시·개발 콘셉트·프로토타입과 실제 제작 프로젝트를 구분한다. 실제 고객 납품·집행·성과로 읽히는 주장에는 증거가 필요하다.
- 메뉴 5개, 별도 상담 CTA, 홈 히어로 3탭, 홈 서비스 8개, WORKS 서비스 10개, TEAM 역할 9개, PROCESS 4단계는 보존한다.
- 새로운 빌드가 준비된 뒤 격리 Playwright 컨텍스트에서 새 코드의 DOM·이미지·키보드·감소 모션을 검증한다. 기존 사용자 IAB 탭 선택·새로고침은 하지 않는다. GET/HEAD/OPTIONS 외 요청은 차단하며 문의를 제출하지 않는다.
- HTTP/소스 검사와 실제 브라우저 렌더링 증거는 별도로 기록한다. 이전 QA의 소적두 기대 문구를 복사해 새 기대값으로 사용하지 않는다.
