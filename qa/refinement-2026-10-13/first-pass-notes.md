# 첫 Chromium 검사 원인 구분

2026-10-13. 영문 화면을 수정하는 작업은 아니다. 첫 검사는 `first-pass/first-pass-chromium.json`에 보존했으며 이후 최종 결과와 합산하지 않는다.

첫 실행은 국문 주요 6경로와 대상 상세 6경로, EN 홈·문의 기능, EN 원본 8경로 비교를 실행했다. 319개 통과·7개 실패, 페이지 오류·콘솔 오류·쓰기 요청은 모두 0이었다.

## 실제 구현 문제 1개

WORKS의 IT 서비스 선택 직후 GSAP 진입 효과가 대시보드 이미지의 CSS `polygon` 가림을 인라인 `inset(0% 1.595% 5.5825%)`으로 잠시 덮었다. 표시 비율 1.35516은 원본 1282/946과 맞았다. 같은 이미지의 카드·상세·확대 검사에서 영구적 비율 손상은 발견되지 않았다. root에게 전달했고 최종 빌드에서 마스크의 우선순위와 해당 이미지의 진입 효과를 보완할 예정이다.

## QA 비교 오류 1개

소적두 카드가 사용하는 새 `redbean-home.png`는 정상 로드됐고 단일 카드였다. DOM의 절대 URL과 API의 상대 URL을 문자열 그대로 비교해 실패했다. 검사 양쪽을 같은 origin의 `URL.href`로 정규화하도록 고쳤다. 사이트 변경은 하지 않았다.

## 기존 EN 전환 중 조기 검사 5개

EN 홈의 5개 서비스 선택에서 불투명도 1을 클릭 직후 요구했다. 기존 `app.js` 서비스 선택은 `isos-motion-enabled`가 없는 경우 380ms의 opacity/translate 전환을 실행하며 EN은 이 기존 분기를 사용한다. 새 한국어 즉시 표시 기준을 영문 전환 중간에 적용한 것이 문제다. EN에만 420ms의 전환 완료 대기를 넣었다. 선택 상태·키보드·이미지 검사는 유지했다. 최종 빌드 후 실제 완료 상태를 다시 확인해야 하며, 이 첫 실패를 영문 기능 회귀로 단정하지 않는다.

## 영문 원본 대조

주요 7경로는 HTML 바이트까지 동일했다. `/en/works/project/all-the-comm/`은 표시 HTML이 동일하고, `site-data` JSON의 `project.order`만 새 사례 추가에 따라 9에서 13으로 달라졌다. 영문 서비스 payload와 공개 사례 집합은 동일했다. 원본은 `before/`에 남겼다.
