# Refinement v1 — 국문 사례 구성·푸터·확대 화면 검수

2026-10-13, 로컬 `http://127.0.0.1:4173`, 1440×900에서 격리된 Playwright Chromium·Firefox·WebKit으로 검수했다. 이 기록은 사례 14개 확장, 사례 반복 축소, 푸터 축소, 책 이미지 배치, 대시보드 로고 가림, 확대 화면 보완과 PROCESS 편집 도구 이미지 교체에 대한 것이다. 이후 요청된 병원 강점 콘텐츠 재구성과 각 주요 메뉴를 더 짧고 풍부한 페이지로 재구성하는 다음 작업은 이 검수 범위에 포함하지 않는다. 다음 구현 전의 v1 스냅샷이다.

기존 사용자 IAB 탭은 선택하거나 새로고침하지 않았다. 브라우저 요청은 GET·HEAD·OPTIONS만 허용했다. 문의 접수, 관리자 변경, 메일 발송과 라이브 배포는 검증 범위가 아니다.

최종 고유 검사는 **1,078/1,078 통과**했다. 런타임 오류·콘솔 오류·쓰기 요청은 모두 0이다. 최종 폴더의 스크린샷은 84장이고, PROCESS의 `*-settled.png` 3장은 500ms/850ms 전환이 실제로 끝난 뒤 추가로 캡처했다. 전환 중간의 첫 캡처도 보존했다.

## 결과 파일과 집계

- `final/results.json`: 국문 주요 6경로와 변경 사례 6경로를 각 3브라우저에서 검사한 원본. 940개 통과, EN 전환 완료 시점 검사 3개 실패가 그대로 남아 있다.
- `viewer-final/viewer-results.json`: 확대 화면 최종 CSS 적용 후 273개 통과. 6사례의 표지·갤러리 총 15개를 3브라우저에서 검사한 45개 이미지 상태와 EN 3건 재검증을 포함한다.
- `process-final/process-results.json`: PROCESS 두 번째 이미지 교체 후 해당 경로만 다시 검사한 결과.
- `final-summary.json`: 위 결과를 의미가 같은 검사 이름으로 연결한 최종 집계. 최초 실패나 재검사를 중복 가산하지 않는다.
- `first-pass/`: 첫 Chromium 319개 통과·7개 실패 원본과 당시 스크린샷. 원인 분류는 `first-pass-notes.md`에 기록했다.
- `before/`: 수정 전 EN 주요 8경로 HTML과 공개 사례 목록.

전체 회귀 943개 항목 중 EN 3개는 조건 완료 재확인 결과로 대체한다. 뷰어 재검사 273개 중 기존 HTTP·이미지 열기·마스크·Escape·EN·오류 확인과 중복되는 항목은 제외하고, 화면 맞춤 경계·원본 크기·다시 맞추기의 새로운 조건 132개만 추가한다. PROCESS의 기존 단계·이미지·감소 모션 조건은 최신 결과로 대체하며 새 편집 도구와 올바른 표기가 적용됐는지만 추가한다. 상세 매핑은 `compile-results.cjs`와 최종 JSON의 `replacements`에서 확인할 수 있다.

## 확인한 동작

홈, ABOUT, PROCESS, TEAM, WORKS, CONTACT에서 공식 메뉴 5개와 별도 문의 CTA를 유지했다. 홈 히어로의 Kings·EzyLens·먹거리사전 3개 사례 탭과 키보드 이동, 홈 서비스 8개, WORKS 서비스 10개, TEAM 역할 9개, PROCESS 단계 4개를 검사했다. 홈 서비스와 회사 소개, ABOUT, TEAM은 사례 이미지를 반복하지 않는다. PROCESS는 단계마다 다른 작업 화면을 표시한다.

공개 사례는 중복 없이 14개이며 EzyLens는 UI/UX 제목과 IT 서비스 단일 분류를 사용한다. 새 사례 4개와 EzyLens·소적두 상세에서 실제 API의 본문 9개 필드, 제목·canonical·출처, 각 표지·갤러리, 원본 확대와 Escape·포커스 복귀, 문의 링크의 사례 slug와 입력란 사전 채움을 확인했다. 문의는 보내지 않았다.

홈 푸터는 초대 문구 1개·36px이며 높이는 브라우저별 274.58~274.60px였다. 내부·상세 푸터는 큰 초대 문구가 없고 178.78~178.80px였다. 이메일·전화·개인정보 링크·대표명·사업자 정보는 남아 있다.

대시보드는 원본 1282×946의 비율을 유지하고 상단 왼쪽 13.5%×6% 부분만 가린다. 카드·IT 서비스 선택 직후·상세·화면 맞춤·원본 확대에서 가림을 확인했다. 책의 표지와 내지 4개는 브라우저에서 읽은 원본 치수가 모두 1352×2000이며, 표지 최대 높이 약648px·2열 내지 최대760px의 비율을 확인했다. 화면 맞춤 모드는 높이900px의 뷰포트에서 모든 대상 이미지가 716px 이하로 들어오고, 원본 크기 모드는 실제 이미지 치수로 표시된다.

## EN 3건의 실패 원인

EN 앱이나 전환 효과는 수정하지 않았다. 기존 전환은 380ms지만 420ms 고정 대기 후 특정 브라우저의 마지막 프레임을 읽으면 opacity가 아직 정확히 1이 아닐 수 있었다. 재검증에서 WebKit IT 패널은 420ms에 opacity `0.999905`, 애니메이션 시간 `384/380ms`를 보고했고, 이후 최대1500ms의 상태 조건 대기 안에 opacity1·애니메이션 없음으로 확정됐다. Firefox 0번, WebKit 5·6번 모두 선택 상태와 최종 가독성이 정상임을 확인했다. 재실행용 `check.cjs`도 고정 시간 대신 이 조건을 사용한다.

EN 주요 7경로의 HTML은 수정 전과 바이트 단위로 동일했다. 자사 상세 1경로는 표시 HTML이 같고 삽입 JSON의 `project.order`만 사례 확장에 따라 9에서13으로 달랐다. EN 서비스 내용과 공개 사례 1개, 홈 탭·문의 사전 채움 기능을 확인했다. 영문 신규 번역이나 리디자인 검수가 아니다.
