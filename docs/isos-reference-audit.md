## 4. 원본의 가독성·감소 모션 한계

**참고할 점**

- 사진 위 글에는 어두운 그라디언트가 함께 변하며, 사진 확대 진행과 글자색 전환을 연결한다(L100, L300–306, L372).
- 큰 제목·짧은 보조 문장·mono 상태표시로 정보 계층을 나눈다. 본문 기본16px/1.5, lede16~20px/1.5, 최대46ch다(L24, L63–69).
- 좌측 설명 sticky와 우측 진행 내용을 나눠 스크롤 중 문맥이 유지된다(L197, L273).
- 같은 장면의 시각 요소와 설명을 함께 변경한다. 장식만 움직이는 것보다 원인과 결과를 읽기 쉽다.

**그대로 가져오면 안 되는 부분**

1. **감소 모션 처리가 불완전하다.** CSS는 animation/transition duration을 .01ms,1회로 줄이고 문자 변형 일부만 초기화한다(L649–653). JS의 `reduce`는 시작 때 한 번 읽으며(L1177), 실제로는 countUp duration에만 사용한다(L1215). HERO·가로 트랙·사진확대·경로·채팅의 scroll 연동은 계속된다. 4.2초 비교 탭 자동전환도 계속되며 탭 클릭을 해야 멈춘다(L1265–1266). 운영체제 설정이 바뀌어도 JS는 다시 읽지 않는다.
2. **별도 모션 정지 버튼이 없다.** 반복 CSS 효과나 자동 탭을 전체 중지하는 제어는 소스에서 확인되지 않았다. tab/page hidden 시 interval 또는 CSS 애니메이션 중지 처리도 없다.
3. **불투명도 낮은 본문과 축소 fit에 주의해야 한다.** 타일의 비활성 텍스트는 매우 옅고(L168–170), data-fit은 화면 높이에 맞춰 묶음 전체를 scale축소한다(L1363–1364). 작은 글을 더 작게 만들 수 있다. 새 사이트에서는 콘텐츠를 숨기거나 본문을 축소하는 대신 장면 높이·배치 조절이 우선이다.
4. **JS 실패 시 완성 화면이 보장되지 않는다.** `.rv`와 단어 wrapper의 초기 상태가 숨김이고, noscript 복구는 없다(L74–77). 강화 효과를 초기화한 뒤에만 숨김/변형을 적용하는 방식이 적합하다.
5. **hover는 핵심 정보를 숨기는 장치가 되지 않아야 한다.** 페르소나 div는 tabindex와 focus-within을 제공하지만 실제 button·Enter/Space 클릭 처리 없이 클릭 클래스도 사용한다(L846–858, L1252). 새 사이트에서는 키보드·버튼 의미를 유지해야 한다.
6. 가로 트랙·긴 pin은 페이지 안의 일반 링크나 폼을 찾아가는 사용자에게 장벽이 될 수 있다. 모든 페이지를 긴 프레젠테이션으로 만들 필요는 없다. 원본 이미지·ISOS 로고·고객 주장·의료/안전 문구는 회사 사이트의 제작 자료가 아니다.

**이름보다 실제 코드를 기준으로 봐야 한다.** v1.1.1의 `count`는 숫자를 세지 않고 scale .9→1만 한다(CSS L865–867). `draw` 역시 실제 SVG dash 경로가 아니라 opacity와 scale .985→1이며 clip-path는 처음부터 inset0이다(L859–863). 반면 Desktop HTML의 CASE는 실제 SVG 경로 길이와 dashoffset을 쓴다(L1279, L1338–1339). 두 참고를 혼동해서 ‘SVG 선 그리기 구현이 이미 있다’고 판단하면 안 된다.

11종 중 실무적으로 전역에 옮길 원칙은 이름별 효과 수보다 **짧은 총시간, 의미 단위, 페이지 내용에 맞는 배정, 정착 후 변형 제거, 즉시 완성 fallback**이다. 발표 덱의 절대 좌표·표·페이지별 숫자 각본을 홈페이지에 복사할 이유는 없다.

## 7. 국문 PC 전역 적용 제안

아래는 분석을 바탕으로 한 제안이며 원본 파일의 사실과 구분한다. 기존 디자인 시스템의 잉크·민트·glacier·Pretendard를 유지하고 참고의 장면 문법을 옮기는 방식이다. 영어와 모바일에 새 모션을 확대하지 않는다.

| 위치 | 먼저 보여줄 내용 | 적합한 모션 구성 | 복제하지 않을 요소 |
|---|---|---|---|
| 홈 | 생각이 실제 결과물로 이어지는 회사 | 제목 의미 단위 mask 등장 → 공식 심볼 장면의 짧은 scroll 전환 → 대표 작업 창 확장 | ISOS 여행 사진·장시간 아치·긴 무한 장식 |
| ABOUT | 회사의 관점과 종합 역량 | 큰 문장 단위 점등, 채널 구성요소가 한 화면으로 합류하는 장면 | 임의 성과 counter·위성 아이콘 목록 |
| PROCESS | 이해→전략→실행→검수의 인과관계 | 한 sticky stage의4단계 강조, 진행선과 설명 동기화. 기존 버튼 선택도 유지 | 모든 설명이 보일 때까지 스크롤만 강제하는 구성 |
| TEAM | 서로 다른 전문성이 어떻게 연결되는가 | 역할 선택에 맞춰 글라스 조형·이름·산출물 연결, 짧은 강조 이동 | 동일 보고서 카드9개·일괄 뒤집기 |
| WORKS | 실제 제작물과 작업 성격 | 현재 이미지 창 열림과 읽기 선 발전, 카테고리 전환의 짧은 텍스트/배치 정착 | UI 캡처 내부 확대·회전·원본 잘림 |
| 사례 상세 | 과제→판단→구현 | 화면은 읽을 수 있게 고정하고 각 단계 진입 시 제목·설명·진행선 강조 | 가상의 실적 타임라인·확인되지 않은 수치 |
| CONTACT | 어떤 일을 맡길지 결정·작성 | 제목과 소개만 짧게 등장, 선택 상태와 검증 응답은 즉각적 | 입력 도중 위치 이동·자동 순환·레이아웃 점프 |
| 개인정보 | 내용 확인 | 제목의짧은 등장과 읽기 위치 표시 정도; 본문은처음부터 읽힘 | 본문 opacity숨김·스크롤 pin·자동 교대 |

### 공통 시간과 제어 권고

- 첫 진입 장면은 전체 약0.9~1.3초, 의미 단위2~6개, 간격55~90ms 정도로 제한한다. 한글을 글자 하나씩 길게 쪼개기보다 줄/어절/강조구를 기준으로 한다.
- 본문은 기본적으로 읽을 수 있게 두고, 장면 초기화가 성공한 대상에만 등장 처리를 적용한다. 모션이 끝나면 transform/filter/clip-path를 제거한다.
- 주요 장면은 실제 자료와 설명을 연결하고, 같은 종류의 연출을 여러 구간 연속 반복하지 않는다. 원본의 230~520vh 높이는 그대로 복사하지 말고 각 페이지의 내용량과 탐색 길이에 맞게 줄인다.
- 진행선·마우스 반응·회전은 viewport 밖과 hidden에서 멈춘다. 반복/자율 모션에는 명시적 정지 제어를 제공하며 제목·작업 화면·폼은 언제나 접근 가능해야 한다.
- 감소모션이 켜지면 단순한 duration축소를 넘어 pin/scrub·자동전환·이미지확장·문자분할 효과를 제거하고 **즉시 완성 상태**를 표시한다. 실행 중 설정 변경도 반영한다.
- 전역효과와 개별포트폴리오효과가 같은 요소의 transform을 동시에 제어하지 않게 소유 대상을 나눈다. 기존 캡처 이미지에는 흔들림·scale·시차를 추가하지 않는다.

## 8. 구현 후 검증해야 할 지점

현재 문서는 정적분석 결과다. 위 확장 제안의 구현·성능·가독성 통과를 뜻하지 않는다. 후속 검수는 다음 지점을 국문 PC에서 표적으로 확인하면 된다.

1. 각 페이지 진입·중간·끝에서 미완성 opacity/clip/transform이 남지 않는가.
2. 1440px, 짧은 데스크톱 높이, 확대된 글씨에서도 sticky 장면의 제목·본문·제어가 화면 밖에 고정되지 않는가.
3. 빠른 스크롤·해시 직행·뒤로가기·필터 변경·키보드 focus 때 즉시 읽을 수 있는가.
4. 모션 정지 및 OS 감소모션 설정을 실행 중 바꿔도 RAF·interval·CSS 반복과 scrub가 실제로 멈추는가.
5. UI 캡처 원본 비율·텍스트·콘셉트/제작자 분류가 유지되는가.
6. 영어·모바일 출력의 코드/시각 변경이 생기지 않았는가.

참고의 강점은 페이지를 읽는 행위와 변화를 연결하는 데 있다. 새 구현에서는 그 원리를 회사의 실제 제작물·업무 방식·문의 흐름에 맞게 적용하는 것이 핵심이다.
