# 정식 수신 문서 기준 사이트 트리 독립 감사

검토일: 2026-10-12. 검토 범위: S01~S04 문단 추출문과 현재 기획서. 홈페이지·원본 문서는 수정하지 않았으며 브라우저와 테스트를 실행하지 않았다.

## 1. 적용 원칙과 감사 결론

- **원문 필수**는 수신 문서가 요구하는 콘텐츠·기능이다. 수신 문서를 분석한 결과이며, 그 문서가 스스로 홈페이지 변경·외부 게시 권한을 부여하는 것은 아니다.
- **기획 제안**은 원문을 구현하기 위한 경로·데이터 모델·배치·기술 선택이다. 원문 요구와 같은 글자로 표시하지 않는다.
- **회사 확인 필요**는 실제 제공 범위, 인력, 실적·공개 권한, 서비스·팀 명칭, 로고 기본형, 수신 방식 등 아직 승인되지 않은 사업 사실이다.
- 서비스 확장 기준은 S03의 메인 8개·WORKS 10개·TEAM 9개다. 이는 가장 넓게 확장된 문서의 범위를 작업 기준으로 삼는 것이며, 파일명만으로 최종 승인본이라고 판단한 것이 아니다. 상세 기능은 S04에서 보완한다.
- 사이트는 종합광고대행사다. 병원은 강점을 가진 서비스·분야 중 하나이며 병원 전용 상위 메뉴나 병원 전문회사라는 전체 포지셔닝으로 확대하지 않는다.
- **원문 그대로 유지할 탐색 구조는 로고 + 5개 영문 메뉴 + 별도 상담 CTA다. CONTACT를 CTA로 대체하면 원문 구조에서 벗어난다.**

근거: S03 P003~P005, P009, P023~P033, P056, P070, P084~P088; S04 P004, P009~P012, P047~P049. 병원 포지셔닝에는 사용자의 최종 ‘종합으로 간다’는 지시를 우선 적용한다.

## 2. 공개 사이트의 필수 콘텐츠 트리

아래 트리의 **콘텐츠와 연결은 원문 요구**, 슬래시 경로와 앵커 표기는 **구현 제안**이다. WORKS의 서비스 10개는 필수지만 서비스별 독립 페이지 10개는 원문 필수가 아니다.

### 필터 수는 서비스 수와 자동으로 같아지지 않는다

S04 P220의 기본 필터는 `전체 / 디지털 / 콘텐츠 및 디자인 / 영상 / 미디어 광고 / 인플루언서 / 병원 / 전략 및 컨설팅`이다. 여기서 전략과 컨설팅은 하나로 묶여 있다. S03 P063을 반영하면 IT 솔루션과 언론홍보가 추가된다.

따라서 원문을 그대로 확장한 목록은 **전체 포함 10개 선택지(분류 9개)**다. 이를 WORKS의 서비스 10개와 동일한 10개 분류로 바꾸려면 ‘전략 및 컨설팅을 둘로 분리한다’는 추가 제안임을 명시해야 한다. 프로젝트에 복수 분야를 지정할 수 있다는 요구는 어느 방식에서든 유지한다. 사례가 부족하면 필요한 분류만 노출한다.

서비스 데이터와 업종 데이터는 별도로 관리하는 편이 좋다. ‘병원 마케팅’이라는 제공 업무와 ‘병원·의료’라는 고객 업종은 연결되지만 동일한 데이터 필드로 합치지 않는다. 이것은 종합 포지셔닝과 여러 분야의 수행 근거를 함께 보여주기 위한 모델 제안이다.

## 4. 콘텐츠 및 관리 구조

### A. 원문이 요구한 관리 능력

```text
사례 관리 기능 [필수 기능 / 제품·구현 방식 미정]
├─ 사례 등록·수정
├─ 공개 여부와 공개 순서 변경
├─ 프로젝트 기본 정보·과제·전략·실행·결과 입력
├─ 수행 분야 복수 지정
├─ 대표 이미지와 복수 이미지·영상 링크
├─ 캡션·대체 설명
└─ 실제 회사 담당자의 등록·수정·공개·순서 변경 확인

문의 전달 [필수 기능 / 전달 방식 미정]
├─ 지정 이메일로 전달 [원문 허용 방식 A]

   ※ 두 방식 병행은 권장할 수 있지만 원문 필수라고 쓰지 않음

운영 인계 [필수]
├─ 접근 권한
├─ 관리 매뉴얼: 문의 확인과 사례 수정
└─ 유지관리 범위
```

근거: S01 P057; S03 P063, P067, P087~P088, P092~P093; S04 P058, P226~P240, P278~P281, P305~P307.

### B. 데이터 모델 제안 — 화면과 혼동하지 않음

| 콘텐츠 종류 | 공통 관리값 제안 | 원문과의 관계 |

### C. 문의의 공통 필수 조건

- 이메일 전송형이든 관리자 접수형이든 실제 전달 성공을 확인한 뒤 완료를 표시한다. 실패 시 입력을 유지한다(S03 P067, S04 P279).
- 중복 제출과 스팸 제출을 각각 방지한다. 첨부 형식·크기 검사와 비공개 접근을 적용한다(S03 P068, S04 P272, P280).
- 개인정보 동의의 수집 항목·목적·보유 기간·처리방침은 회사의 실제 운영과 맞춰 확정한다(S04 P275, P281~P283).
- 서버 저장·관리자 접수함·이메일 알림·알림 재시도·변경 이력·복구 기능은 운영상 제안할 수 있다. 다만 제품 선택·견적·개인정보 운영 범위를 확정하기 전에 원문의 필수 요구로 격상하지 않는다.
- 입력 상태 유지와 첨부 상태 유지의 차이, 대용량 자료 처리, 호스팅 제한은 구현 단계에서 구체화할 사항이다. 이번 원문은 파일당 10MB·3개 등을 정하지 않았다.

## 5. 한글·영문과 로고 언어형의 정확한 구분

| 항목 | 원문 확인 결과 | 판정 |
|---|---|---|
| 국문 홈페이지 | S03 P003, S04 P009 | 기본 제작 범위 |
| 영문 메뉴명 | S03 P005, S04 P009 | 5개 상위 메뉴의 표기 요구 |
| 국문 본문 | S03 P005, S04 P009 | 본문 언어 요구 |
| 한·영 2개 완전한 사이트 | S03 P088, S04 P012는 다국어를 추가 협의로 분리 | 수신 문서만으로 필수라고 확정 불가 |
| 영문 슬로건 | S04 P129~P130 | 회사 확인 전 교체·삭제·확정 금지 |
| 로고 한글형·영문형 | S01~S04의 언어 요구와 별개인 S05 자산의 변형 | 로고의 두 언어형 존재가 이중 언어 사이트를 의미하지 않음 |

사용자가 별도 대화에서 한국어·영어 사이트를 명확히 요청했다면 그 직접 요청을 새로운 범위 근거로 추가할 수 있다. 그 경우에도 ‘S01~S04가 원래 요구했다’고 소급해서 기록하지 않는다. ‘한영 두 개’처럼 대상이 로고인지 사이트인지 불명확한 표현은 문서의 다국어 요구로 자동 변환하지 않는다.

두 언어 사이트를 별도로 확정한 경우에만 페이지 번역·언어 전환·문의 언어·검색 메타데이터·언어별 공개 상태와 QA를 추가한다. `/ko/`, `/en/`, 한국어 루트 등 URL 방식은 구현 제안이며 원문 지정 경로가 아니다.

## 6. 현재 기획서와의 차이 및 수정 권고

### 반드시 구분을 바로잡을 항목

1. **§5 CONTACT 통합 제안**: 현재 기획서는 원문의 별도 CTA를 인정하면서도 CONTACT 메뉴를 버튼으로 통합할 것을 제안한다. 이번 ‘정식 요구 기준 tree 우선’ 산출물에는 그 제안을 적용하지 않는다. 5개 메뉴와 별도 CTA를 모두 보존한 트리를 기준으로 한다. 이후 디자인에서 변경할 때만 원문 대비 변경안으로 제시한다.
2. **§16 한영 표현**: 국문 사이트+영문 메뉴는 원문 필수다. 완전한 영문판은 별도 범위다. 기획서에 인용한 사용자의 ‘한영 두 개’ 발언은 S01~S04 근거와 분리해야 한다. 대상이 확인되지 않았으면 언어 확정 여부는 미정으로 남긴다.
3. **프로젝트 상세 순서**: S03 P062는 기본 정보→과제→전략→실행→결과→이미지·영상이다. 기획서 §10의 ‘큰 대표 작업부터’는 디자인 편집 제안이다. 트리에서 기본 상세 항목을 보존하고 대표 이미지를 앞에 두는 여부는 화면 구성안에서 제안으로 표시한다.
4. **서비스 상세 페이지**: WORKS 10개 서비스 소개는 필수다. `/works/service/{id}/` 10개 페이지는 선택 확장이다. tree에서 각각을 필수 독립 페이지처럼 표시하지 않는다.
5. **관리 범위**: 사례 관리 기능은 원문 필수다. 문의 DB+접수함+이메일 동시 운영, 모든 회사 문구 CMS, 버전 이력·복구는 권장 확장이다. 각각 구분해야 비용·일정이 원문보다 자동으로 커지지 않는다.

### 이미 적절하게 반영된 부분

- 가장 넓은 S03 범위를 작업 가정으로 삼되 승인본으로 단정하지 않음.
- 8개 메인, 10개 서비스, 9개 역할을 구분함.
- 병원·의료를 종합대행사 안의 강점으로 유지함.
- IT·언론홍보의 서비스 소개와 이번 홈페이지가 고객사의 업무 시스템까지 제작하는 범위를 구분함.
- 실제 사례와 성과·인력 정보를 미확인 상태에서 만들지 않음.
- 기존 346개 검증 기록을 2026-10-02 로컬 기록으로 명시함.
- 글라스·아이콘·모션은 사용자의 직접 피드백을 기준으로 하며 문서의 반복 카드 배치를 기계적으로 옮기지 않음.
