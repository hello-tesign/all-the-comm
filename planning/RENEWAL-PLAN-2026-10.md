# 올더커뮤니케이션 홈페이지·SNS 리뉴얼 기획안

작성일: 2026-10-02 / 상태: 초기 기획 기록, 로컬 구현으로 진행 / 공개·계정 변경·언론 배포 미실행

> **구현 2차 수정 기준 — 이 문서의 초기 시각 규정보다 우선한다.** 사용자는 1차 화면의 가로선·번호·영문 서비스 목록을 보고서처럼 느낀다고 지적하고 글라스 카드와 아이콘으로 교체하도록 요청했다. 이에 서비스 영역을 짙은 녹색 배경, 반투명 패널, 업무별 맞춤 SVG 아이콘, 포인터에 반응하는 조명으로 바꿨다. 아래의 유리 효과·아이콘·카드에 대한 일괄 금지와 텍스트 목록 권장은 초기 해석의 기록이며 더 이상 적용하지 않는다. 현재 구현 기준은 `design-system/MASTER.md`, 확인 결과는 `qa/HANDOFF.md`를 따른다. 병원을 메인으로 삼지 않는 종합광고대행사 포지셔닝과 허위 실적 금지는 유지한다.

## 1. 목표와 역할

올더커뮤니케이션의 중장기 브랜드 자산이 될 대표 홈페이지를 만든다. 사용자가 제시한 지향점은 칸 광고제에 나갈 정도의 회사로 보이는 크리에이티브와 완성도다. 회사 고유의 아이디어, 시각적 정교함, 모션, 실제 수행 증거, 모바일 사용성을 함께 설계한다. 홈페이지를 중심으로 SNS와 회사 소개 자료를 확장한다. 10월 말 행사는 활용 접점 중 하나이며 납기나 품질을 결정하는 우선 조건이 아니다.

- 김연환 대표: 회사의 사업 방향·실제 수행 역량·대표 프로필·공개 가능 실적 확인.
- 사용자: 마케팅·광고 전문대행사 올더커뮤니케이션의 홈페이지와 SNS 제작 주체.
- 확정된 사업 중심: 업종을 한정하지 않는 종합광고대행사. 병원 마케팅은 강점을 가진 분야 중 하나이며 메인 포지셔닝이 아니다.
- 아직 미정: 우선 수주 서비스, 업종별 공개 가능한 실적, 기존 SNS 계정·운영 주체. 행사 정보는 부차 자료다.
- 품질 운영 원칙: 기준 미달 시 해당 단계로 돌아가 수정하고 다시 검증한다. 일정만으로 미완성 결과를 통과시키지 않는다.
- 1차 품질 목표: 사용자가 제시한 ‘기존 30점 → 리뉴얼 90점’을 기준으로 삼는다. 기존 30점은 사용자의 비교 표현이며 자동 측정 결과가 아니다. Awwwards·Dribbble·Behance에서 선별한 우수 작업과 나란히 검토할 수 있는 디자인·경험 완성도를 지향한다.

성공의 기준은 ‘사이트가 새로워졌다’에서 끝나지 않는다. 방문자가 첫 화면에서 업종과 업무를 이해하고, 사례에서 맡길 수 있는 범위를 확인하고, 문의나 미팅으로 이동하는 흐름까지 완성한다.

## 3. 브랜드와 콘텐츠 방향

확정 포지셔닝: **전략·제작·광고 운영을 아우르는 종합광고대행사.** 특정 업종을 회사의 대표 정체성으로 설정하지 않는다. 병원 마케팅에 대한 강점은 관련 수행 사례와 분야별 설명에서 구체적으로 증명한다.

서비스와 업종을 두 축으로 분리한다. ‘전략 / 광고 운영 / 웹·디자인 / 콘텐츠·영상 / 언론·홍보’는 맡기는 업무이며 사이트의 중심 탐색 기준이다. 업종은 실제 포트폴리오에 근거해 동등한 분류로 구성한다. 병원·의료는 그중 하나다. 대표 사례는 제작 완성도·문제 해결의 설득력·수행 범위의 다양성으로 선정하며 병원 우선 배치나 고정 비율을 두지 않는다.

방문자가 답을 얻어야 하는 질문은 세 가지다.

1. 우리 브랜드의 어떤 일을 맡길 수 있는가?
2. 비슷한 일을 실제로 수행했는가?
3. 누가 맡고, 무엇을 만들며, 어떻게 보고하는가?

메인 카피 초안:

> 브랜드를 설계하고.
> 콘텐츠를 만들고.
> 광고를 운영합니다.

보조 설명 초안:

> 올더커뮤니케이션은 브랜드 전략부터 홈페이지, 콘텐츠 제작, 광고 운영까지 수행하는 종합광고대행사입니다.

문구는 업무 범위를 정리하기 위한 초안이다. 대표 인터뷰와 사례 분석에서 회사 고유의 표현을 찾아 최종 카피를 만든다. 메인은 종합적인 문제 해결과 제작·운영 역량을 보여주고, 업종별 전문성은 해당 사례와 분야 설명에서 증명한다.

편집 기준:

- ‘최고의 파트너’, ‘성공을 함께’, ‘차별화된 솔루션’, ‘고객 감동’, ‘혁신적인 시너지’ 삭제.
- 추상적인 약속 한 줄 대신 담당 업무·기간·제작물·운영 방식 중 최소 하나를 명시.
- 조직도나 팀 수는 현재 운영 구조를 확인한 뒤 게재. 협력 제작과 직접 수행의 범위를 정확하게 기술.
- 확인되지 않은 성과 숫자·고객 로고·언론 보도·대표 이력을 만들지 않는다.
- 장식용 이미지·아이콘·스톡 사진을 배제. 실제 작업물과 현장 사진만 정보로 사용.
- 자료가 부족하면 타이포그래피와 실제 산출물 일부로 구성한다. 가짜 포트폴리오를 만들지 않는다.

## 4. 디자인 시스템

### 90점에 필요한 디자인과 마케팅의 결합

디자인을 깊이 이해하는 회사라는 인상은 한글 조판, 여백의 비례, 정렬, 시각적 긴장과 균형, 실제 작업물의 크롭, 색 사용, 화면 간 리듬에서 드러나야 한다. 메인 첫 화면뿐 아니라 사례 상세·메뉴·문의·모바일까지 같은 아트디렉션을 유지한다.

마케팅 전문성은 사례에서 ‘누구의 어떤 문제를 발견했는가 → 왜 이 메시지와 접점을 선택했는가 → 어떻게 제작·운영했는가 → 무엇을 확인하고 조정했는가’로 보여준다. 이 내용을 보고서형 카드 네 개에 넣지 않는다. 결과물을 충분히 크게 보여주면서 필요한 위치에 짧은 설명과 근거를 편집한다. 확인된 성과가 있으면 기간·범위와 함께 제시하고, 없으면 실제 산출물·판단·운영 범위를 명확히 보여준다.

### 금지하는 구성

- 아이콘·짧은 제목·두 줄 설명을 같은 둥근 카드로 반복하는 서비스 영역.
- 대시보드처럼 숫자 타일·배지·작은 박스를 채운 회사 소개.
- 모든 섹션에 같은 작은 영문 라벨·중앙 제목·3열 카드를 반복하는 구성.
- 실적 근거 없이 ROAS·프로젝트 수·고객 수를 장식용 숫자로 사용.
- 관련 없는 3D 구체, 보라색 발광 그라디언트, 유리 효과, 장식용 스톡 이미지·아이콘.
- 본문과 관계없는 거대한 영문, 상투적인 AI 문구, 가짜 후기·고객 로고.
- 모든 콘텐츠를 같은 reveal 효과로 처리하거나 움직임으로 빈약한 구성을 가리는 방식.

사용자가 말한 ‘AI스러운 디자인’은 위와 같은 반복적이고 회사 고유성이 없는 표현을 검수 가능한 금지 조건으로 구체화한다. 대체 구성은 실제 작품을 크게 보여주는 화면, 크기 차이가 있는 비대칭 편집, 짧은 텍스트 목록, 이미지와 설명의 의도적인 배치다. 단순히 카드의 모서리를 각지게 바꾸는 것으로 해결하지 않는다.

기획 문서의 표는 작업 명세이며 홈페이지에 표·카드로 그대로 옮길 레이아웃이 아니다. 디자인 시스템은 비례·타이포·상태·동작의 일관성을 규정하고, 섹션마다 같은 박스를 반복하도록 강제하지 않는다.

권장 크리에이티브 방향: **한 프로젝트가 여러 접점에서 완성되는 과정을 체험하는 회사 포트폴리오.** 내부 작업명은 ‘하나의 판단, 여러 개의 접점’이다. 공개 슬로건으로 확정한 문구는 아니다.

대표 장면에서는 실제 프로젝트의 한 메시지를 시작점으로 잡는다. 스크롤에 따라 그 메시지가 홈페이지, 콘텐츠, 영상, 인쇄물에 어떤 식으로 달리 구현됐는지 같은 화면 안에서 연결해 보여준다. 마지막에는 ‘어떤 고객 문제 때문에 이렇게 만들었는가’를 밝힌다. 예쁜 결과물뿐 아니라 대행사의 판단과 실행 범위를 체험하게 하는 구조다.

회사 로고의 중첩된 선 형태를 확인해 프레임·장면 전환의 고유한 규칙으로 발전시키는 안을 우선 실험한다. 어느 회사 로고를 넣어도 성립하는 화면이라면 콘셉트 단계에서 재작업한다. 사진과 산출물의 미술 방향, 크롭, 영상 편집, 캡션까지 한 체계로 설계한다.

큰 한글 제목, 정렬이 분명한 여백, 작업물의 대담한 크롭, 선과 번호를 사용한다. 스티커·카드 그림자·둥근 박스의 반복은 사용하지 않는다. 병원 분야라도 흰 가운, 청진기, 의료 십자 같은 상징으로 화면을 채우지 않는다.

`ui-ux-pro-max` 검색 결과는 참고만 했으며 자동 추천의 스티커·굵은 테두리·장식 아이콘 스타일은 이번 사용자 요구에 맞지 않아 채택하지 않았다. 상세 규칙의 기준 문서는 `design-system/MASTER.md`다.

로고의 공식 원본과 유지 범위를 확인한다. 전면 리뉴얼을 곧바로 법인 로고 교체로 해석하지 않는다.

## 5. 홈페이지 구조와 모션 장면

메인 메뉴: **수행 사례 / 하는 일 / 회사 / 인사이트 / 문의**. 수행 사례는 업무와 업종으로 탐색하며 모든 업종에 같은 상세 페이지 구조를 적용한다. 특정 업종을 최상위 메뉴로 분리하지 않는다.

아래 순서는 방문자가 이해할 정보의 흐름이다. 동일한 높이·동일한 제목·동일한 카드로 7개 섹션을 쌓는 와이어프레임이 아니다. 대표 사례는 몰입감 있게, 서비스는 간결하게, 판단 근거는 읽기 좋게 서로 다른 밀도와 길이로 편집한다.

| 순서 | 방문자에게 보여줄 내용 | 모션 연출 | 이동 |
|---|---|---|---|
| 1. 첫 화면 | 종합광고대행사의 역량을 설명하는 한글 제목과 대표 작업 1점 | 브랜드의 선·프레임 규칙으로 제목과 실제 작업이 한 장면을 형성 | 수행 사례·문의 버튼 즉시 노출 |
| 2. 대표 사례 | 완성도·문제 해결·수행 범위의 다양성으로 선정한 3건 | 같은 프로젝트의 메시지가 홈페이지·SNS·제작물로 변형되는 대표 장면 | 각 사례 상세 |
| 3. 맡길 수 있는 일 | 전략·광고 운영 / 홈페이지·디자인 / 콘텐츠·영상 / 언론·홍보 | 업무를 선택하면 실제 산출물과 담당 범위가 전환 | 서비스 상세·관련 사례 |
| 4. 분야별 경험 | 업종별 과제를 어떻게 이해하고 실행했는지 | 사례 선택에 따라 실제 산출물과 판단 근거가 전환 | 관련 사례·분야 설명 |
| 5. 수행 방식 | 진단 → 실행 계획 → 제작·운영 → 보고 | 각 단계에서 실제로 받는 문서·산출물을 순차 공개 | 문의 |
| 6. 회사·대표 | 김연환 대표의 역할·이력·관련 수행 경험 | 실제 인물 사진과 짧은 문장, 정적인 읽기 중심 | 회사·대표 상세 |
| 7. 소식·문의 | 발행된 콘텐츠·확인된 보도·프로젝트 문의 | 짧은 전환과 명확한 입력 피드백 | 소식 상세·문의 완료 |

메인에서 고정 스크롤 장면은 최대 2개. 각 장면은 PC에서 180–220vh를 초기 상한으로 두고 검증한다. 모든 사례를 보기 위해 강제 가로 스크롤을 통과하게 만들지 않는다. 모바일은 고정 구간을 일반 세로 흐름으로 바꾼다.

모션은 풍부하게 사용하되 읽기를 기다리게 하지 않는다.

- 첫 화면: 600–900ms 내 주요 내용과 버튼이 보이게 구성.
- 일반 장면: 400–700ms 전환, 60–100ms 간격의 행 단위 등장.
- 버튼·탭: 160–220ms 피드백.
- 화면을 벗어난 영상·루프는 정지. 자동 재생 영상은 무음이며 정지 수단 제공.
- 모션 감소 설정: pin·parallax·텍스트 분할을 해제하고 완성된 콘텐츠를 표시.
- JS 실패 시에도 핵심 내용과 문의 링크를 읽을 수 있는 구조.
- 커서 추종, 무한 회전 배지, 의미 없는 숫자 카운터, 강제 인트로 대기는 제외.

### 상세 페이지

- 수행 사례 목록과 사례 3건: 고객의 상황 → 담당 범위 → 제작·운영 과정 → 결과 → 관련 문의.
- 분야별 설명: 실제 실적이 뒷받침되는 분야를 동일한 구조로 소개. 병원·의료 강점도 여기에서 업무 범위·산출물·사례로 구체화.
- 서비스: 현재 제공 가능한 업무 4개 묶음과 각 범위·산출물. 확인되지 않은 서비스는 제외.
- 회사·대표: 소개·현재 역할·확인된 이력·협업 체계·연락처.
- 소식: 회사 콘텐츠와 외부 보도를 구분. 보도는 원문·날짜·매체 확인 후 등록.
- 프로젝트 문의: 회사·기관명, 이름, 회신 연락처, 요청 내용, 필요한 동의. 예산·일정은 선택.

문의는 전송 중·완료·오류·중복 제출 방지를 포함한다. 완료 화면만 보이는 것으로 끝내지 않고 실제 수신 여부까지 공개 전 확인한다.

## 6. SNS 제작 범위

우선 채널 제안은 인스타그램과 네이버 블로그다. 현재 계정, 운영 이력, 고객 유입을 확인해 확정한다. 인스타그램은 작업의 시각적 확인, 블로그는 수행 과정과 업무 설명에 초점을 둔다. 모든 채널을 동시에 늘리지 않는다.

초기 제작물 권장안:

| 항목 | 수량 | 내용 |
|---|---:|---|
| 프로필 체계 | 채널별 1세트 | 회사명·소개·링크·커버 규칙 |
| 고정 피드 | 3개 | 하는 일 / 대표 사례 / 맡기는 방법 |
| 사례 피드 | 3개 | 다양한 업무·업종의 실제 산출물과 역할 |
| 업무·관점 피드 | 3개 | 홈페이지·콘텐츠·광고 운영의 구체적인 판단 기준 |
| 짧은 영상 | 3개 | 작업물 전개 / 사례 수행 과정 / 대표의 업무 설명 |
| 블로그 글 | 3개 | 회사와 업무 / 대표 수행 사례 / 프로젝트 진행 과정 |
| 재사용 템플릿 | 4종 | 사례, 업무 설명, 대표 관점, 소식 |

총 피드 9개와 별도 짧은 영상 3개를 초기 제작 규모로 제안한다. 사례 원본과 촬영 가능 여부에 따라 최종 수량을 고정한다. 한 장의 사진을 9개로 나누는 피드 구성은 사용하지 않는다.

하나의 검증된 사례 원고에서 홈페이지 상세, 피드 요약, 영상 스크립트, 블로그 글을 파생한다. 채널별로 새로운 실적이나 숫자를 덧붙이지 않는다.

병원 관련 콘텐츠는 고객 확보 성과만 강조하기보다 실제 설계·제작·운영 판단을 보여준다. 치료 효과·환자 후기 등 의료광고 판단이 필요한 소재는 해당 병원 검토를 거쳐 공개 범위를 정한다. 이 문서는 의료광고 적법성 판단을 수행하지 않는다.

지속 운영은 제작 납품과 구분한다. 권장 시작 빈도는 주 2개 피드·2주 1개 영상·월 2개 심층 글이며 담당자와 실제 제작 여력을 확인해 확정한다.

## 7. 언론 홍보와 대외 접점

순서는 **실제 공개할 내용 확보 → 홈페이지 품질 검증·공개 → SNS 확장 → 언론 자료 배포 → 지속적인 사례·관점 발행**으로 잡는다. 행사 일정에 맞추기 위해 홈페이지 완성도를 낮추지 않는다.

언론 자료의 중심은 리뉴얼 자체보다 확인 가능한 사업 내용이다. 다양한 분야의 실제 수행 경험, 새로 정비한 서비스, 대표가 제시할 수 있는 구체적인 현장 관점을 인터뷰하여 기사 소재로 만든다. 병원 분야는 관련 기사 소재가 있을 때 다룬다.

준비물:

- 회사 소개 원고 1종과 핵심 사실표.
- 김연환 대표 프로필·공식 사진·인터뷰 질문 및 답변 초안.
- 검증된 사업 내용 중심의 보도자료 초안 1종.
- 공개 허용된 사례 이미지·캡션·담당 역할.
- 기자가 확인할 수 있는 웹 링크와 연락 창구.
- 행사에서 공유할 회사 소개 링크·QR, 같은 디자인의 간단한 소개 자료.

보도자료 제목은 서비스 범위와 사실 확인 후 작성한다. 현재는 ‘병원 전문 1위’, ‘매출 몇 배’, ‘전문 조직 신설’ 등을 주장할 근거가 없다. 배포와 실제 게재는 별개로 기록한다.

행사 전용 페이지는 행사 정보가 확정되고 주최 측 맥락에 맞을 때만 만든다. 그 전에는 회사·대표 소개 페이지를 링크 목적지로 사용한다. 아직 열리지 않은 행사의 성과를 먼저 게재하지 않는다.

## 8. 제작 범위와 기술 판단

현재 작업 폴더에 기존 사이트 소스가 없다. 서버·관리자·도메인 설정·문의 수신 방식을 조사하기 전에는 프레임워크나 이전 방식을 확정하지 않는다.

권장 구조는 검색 가능한 HTML을 먼저 제공하고 필요한 장면에만 모션을 붙이는 방식이다. 관리자에서는 사례·소식·대표 소개를 갱신할 수 있어야 하며, 모션 구성을 매번 수정하지 않아도 콘텐츠를 추가할 수 있게 한다.

우선 제작 범위: 홈페이지 메인·서비스·사례 목록/상세 3건·회사/대표·소식·문의, 디자인 시스템. 분야별 설명은 확보된 실적에 따라 추가한다. 후속 확장: SNS 초기 세트·언론 자료 초안. 행사 공유 링크는 필요 시 추가한다.

중장기 운영에서는 사례를 구조화해 업종·업무·기간·담당 범위·산출물·성과 근거로 관리한다. 초안/공개 상태, 이미지 교체, 소식 추가, 메인 추천 순서를 관리자가 변경할 수 있게 설계한다. 모든 업종을 같은 사례 템플릿으로 확장한다. 분기마다 콘텐츠와 문의 흐름을 검토하고, 정기적으로 링크·폼·성능·의존성 상태를 확인하는 운영 문서를 납품한다.

별도 범위 확인: 사진·영상 신규 촬영, 지속 SNS 운영, 유료 광고 집행, 실제 언론 배포 비용, 로고 변경. 이번 기획에서 실행하거나 비용을 집행하지 않았다.

공개 전에는 기존 URL·검색 노출·문의 수신·도메인 연결과 되돌리기 절차를 확인한다. 프리뷰 검증과 실제 도메인 공개 검증을 구분한다.

## 9. Playwright와 품질 통과 기준

| 검증 | 대상과 통과 기준 |
|---|---|
| 화면 | 360·390·768·1024·1440·1920px, 한글 잘림·겹침·가로 넘침 없음 |
| 브라우저 | Chromium·Firefox·WebKit. 실제 iPhone/Android는 별도 최종 확인 |
| 탐색 | 메뉴·사례·서비스·대표 소개·문의의 주요 경로와 뒤로 가기 정상 |
| 모션 | 시작·중간·끝 스크린샷, 역방향 스크롤, 크기 변경, 직접 링크 진입 확인 |
| 모션 감소 | reducedMotion=reduce에서 모든 정보 표시, 긴 고정 구간 제거 |
| 입력 | 필수값 누락·정상 입력·실패·재시도·중복 클릭 검증 |
| 수신 | 테스트 환경에서 자동 검증 후 지정된 공개 환경 테스트 문의의 실제 수신 확인 |
| 접근성 | 키보드 이동·보이는 포커스·폼 레이블·제목 구조·대비 확인 |
| 이미지·링크 | 누락·깨짐·불필요한 빈 링크·페이지 예외 없음 |
| 공유·검색 | 제목·설명·OG·canonical·사이트맵·리디렉션 확인 |
| 시각 검수 | 자동 캡처를 사람이 검토. 기능 통과와 디자인 품질을 별도로 판정 |

정적인 시각 비교에서는 애니메이션을 안정화한다. 실제 모션 검증은 별도 시나리오로 진행한다. 애니메이션을 꺼 놓은 스크린샷만으로 모션 품질을 통과시키지 않는다.

성능 목표는 실사용 75백분위 LCP ≤2.5초, INP ≤200ms, CLS ≤0.1이다. 공개 전에는 고정된 환경의 실험실 측정으로 문제를 찾고 공개 후 실제 사용자 데이터로 확인한다. Playwright 화면 캡처만으로 Core Web Vitals를 달성했다고 주장하지 않는다.

참고: [Web Vitals](https://web.dev/articles/vitals), [Playwright emulation](https://playwright.dev/docs/emulation).

## 10. 제작 단계와 품질 반복

달력상 공개일보다 아래 단계별 통과 기준을 우선한다. 콘텐츠와 제작 리소스를 확인한 뒤 일정을 산정한다.

| 단계 | 결과물 | 다음 단계로 넘어갈 조건 |
|---|---|---|
| 1. 브랜드·사례 조사 | 대표 인터뷰, 실제 사례 분석, 고객의 의뢰 이유 | 종합 역량·차별점·증거가 구체적인 문장으로 정리됨 |
| 2. 아트디렉션 비교 | 서로 다른 콘셉트 3개의 핵심 화면·짧은 모션 연구 | 회사 고유성·명료함·제작 확장성을 비교해 한 방향 선정 |
| 3. 대표 경험 제작 | 메인 시작→사례 전개→문의 진입을 PC·모바일로 구현 | 실제 콘텐츠로 시각·모션·사용성 기준 통과 |
| 4. 시스템 확정·전체 제작 | 토큰·컴포넌트·전체 페이지·콘텐츠 관리 | 페이지가 늘어도 품질과 운영 규칙이 유지됨 |
| 5. 검증·재작업 | Playwright 결과, 화면·영상 비교, 결함 목록 | 주요 결함 해소, 시각 기준과 실제 수신 검증 통과 |
| 6. 공개·채널 확장 | 홈페이지 공개 검증, SNS·언론 자료 적용 | 실제 도메인에서 기능 확인, 동일 브랜드 체계로 확장 |

콘셉트 3안은 전체 사이트 3개를 만드는 작업이 아니다. 같은 사례 자료로 첫 화면과 핵심 전환을 비교하는 짧은 실험이다. 권장안인 ‘여러 접점으로 전개되는 프로젝트’ 외에 ‘제작 과정의 편집 기록’, ‘타이포그래피 중심의 브랜드 무대’를 비교한다. 선택되지 않은 스타일을 한 화면에 혼합하지 않는다.

### 품질 판단표

1차 목표 90점은 프로젝트 내부 검수의 기준이다. 플랫폼 공식 점수나 수상 여부로 환산하지 않는다. 아래 배점은 비교와 결함 추적을 위한 것이며 실제 제작 결과를 보기 전에 점수를 부여하지 않는다.

| 평가 항목 | 배점 | 필요한 근거 |
|---|---:|---|
| 고유한 콘셉트·아트디렉션 | 25 | 선정 레퍼런스와 비교한 독자적인 시각·서사, 대표 장면 |
| 타이포그래피·편집·이미지 완성도 | 20 | PC·모바일의 한글 줄바꿈·간격·크롭·장면 간 리듬 |
| 마케팅 설득력·사례의 깊이 | 20 | 대상 고객·문제·선택의 이유·실행·확인 가능한 결과 |
| 모션·인터랙션 | 15 | 시작·전환·정지·역방향·직접 진입 시 동작 기록 |
| 모바일·사용성·접근성 | 15 | 작은 화면의 독립적인 구성, 탐색·문의·모션 감소 검증 |
| 성능·구현·운영 안정성 | 5 | 성능 측정·Playwright·수신·콘텐츠 추가 검증 |
| 합계 | 100 | 목표 90점 이상 |

합계 90점 이상과 각 항목 배점의 80% 이상을 함께 요구한다. 금지한 카드·상투적인 이미지·허위 성과, 핵심 기능 오류, 모바일 내용 누락은 합계와 관계없이 탈락이다. 기능 안정성을 낮은 배점으로 상쇄할 수 없다. 점수에는 비교 화면과 판단 근거를 붙이고 미검증 항목은 통과로 처리하지 않는다. 제작자의 자기평가만으로 ‘90점 달성’을 선언하지 않고 사용자의 시각 검토에서 제기된 문제도 같은 결함 목록에 반영한다.

벤치마크는 전체 경험, 브랜드 전개, 화면의 세부 완성도로 나누어 선별한다. Awwwards에서는 실제 사이트의 탐색·모션·모바일을, Behance에서는 하나의 정체성이 다양한 제작물로 이어지는 방식을, Dribbble에서는 타이포·구도·짧은 인터랙션을 비교 대상으로 삼는다. 게시됐다는 사실만으로 품질을 인정하거나 콘셉트 화면을 실서비스 성능의 증거로 사용하지 않는다.

초기 조사 자료는 [Awwwards의 에이전시 사이트 목록](https://www.awwwards.com/websites/design-agencies/), [Locomotive의 타이포그래피·모션 발표 자료](https://assets.awwwards.com/assets/files/live-presentation.pdf), [Behance의 BOLDIST 웹디자인 프로젝트](https://www.behance.net/gallery/214472905/BOLDIST-Design-Studio-Website-UXUI), [Monforte 브랜드·SNS 프로젝트](https://www.behance.net/gallery/141486655/Monforte-Studio-Brand-Identity-Social-Media), [Dribbble의 Orizon 작업 목록](https://orizon.dribbble.com/)이다. 이번에는 공개 소개를 확인한 후보이며, 최종 디자인 참고작은 실제 화면·모션·모바일을 확인하고 선택한다. 형태를 복제하지 않고 무엇을 어떻게 해결했는지 비교한다.

[Cannes Lions Digital Craft](https://www.canneslions.com/awards/lions/digital-craft)는 디지털 경험의 실행과 경험을 주요 판단 기준으로 설명한다. 아래는 그 방향을 참고해 이 프로젝트에 적용하는 내부 검수 기준이다. 실제 수상·출품 자격 판정표가 아니다.

| 항목 | 통과 질문 | 재작업 신호 |
|---|---|---|
| 회사 고유성 | 회사명과 로고를 가려도 고유한 시각·서사가 남는가? | 다른 대행사에 그대로 사용할 수 있는 템플릿 |
| 시각 완성도 | 한글 줄바꿈·크기·간격·이미지 크롭에 일관된 의도가 있는가? | 거대한 영문·작은 한글, 반복 카드, 임시 이미지 |
| 모션 | 전환이 내용과 브랜드를 설명하고 정지 화면도 완성되는가? | 장식만 움직이거나 효과가 읽기를 방해함 |
| 종합 역량과 전문성 | 다양한 업무를 수행하는 역량과 분야별 이해가 실제 사례로 보이는가? | 특정 업종 전문회사로 오인되거나 서비스 나열만 있음 |
| 실적의 설득력 | 문제·판단·실행·결과를 실제 자료로 설명하는가? | 썸네일만 있거나 역할·성과 근거가 없음 |
| 사용성 | 처음 온 사람이 업무·사례·문의에 바로 접근하는가? | 긴 인트로·강제 스크롤·발견하기 어려운 메뉴 |
| 모바일·접근성 | 작은 화면과 모션 감소에서도 완결된 경험인가? | PC 화면 축소, 핵심 내용 숨김·잘림 |
| 기술·운영 | 빠르게 읽히고 오류 없이 작동하며 콘텐츠를 추가할 수 있는가? | 테스트 실패, 실제 수신 미확인, 일회성 하드코딩 |

각 회차는 **화면·동작 캡처 → 기준별 결함 기록 → 원인 분류 → 해당 단계 수정 → 같은 조건으로 재검증**한다. Playwright 통과는 기능 검증이며 미적 완성도의 자동 판정이 아니다. 수치 점수만으로 완성도를 선언하지 않는다.

레이아웃 문제는 디자인으로, 모션 문제는 동작 설계로, 회사 고유성 부족은 콘셉트로 돌아간다. 같은 문제가 두 회차 연속 남으면 작은 CSS 조정을 멈추고 구조나 방향을 바꾼다. 이전 버전과 변경 이유·PC/모바일 비교 화면·미해결 항목을 보존한다. 모든 주요 기준이 통과하고 남은 문제가 명시될 때까지 반복한다. 추가 자료가 필요한 문제는 생성 이미지나 가상 실적으로 덮지 않고 필요한 원본을 특정한다.

공개 후에도 실제 이용 데이터를 바탕으로 사례 탐색과 문의 경험을 개선한다. 구조·브랜드 원칙은 유지하며 일시적인 유행에 맞춰 전체를 반복 교체하지 않는다.

## 11. 착수에 필요한 최소 자료

1. 병원 포함 공개 가능한 사례 3건: 고객명 공개 가능 여부·기간·업무 범위·원본 제작물·확인 가능한 결과.
2. 현재 제공하는 서비스와 우선 수주 분야, 직접 수행/협력 제작 범위.
3. 김연환 대표의 공식 프로필·사진·인터뷰 가능 일정.
4. 기존 로고 원본, 회사 소개 자료, 홈페이지 관리자·호스팅 접근 방식, SNS 계정 목록.
5. 공개 가능한 언론 기사나 외부 활동. 행사명·날짜·역할은 활용 시 추가 확인.

접근 정보는 후속 구현 단계에서 안전한 방식으로 전달받는다. 기획 문서에 비밀번호·토큰을 기록하지 않는다.

측정 항목은 사례 열람, 서비스 상세 진입, 문의 시작·완료, SNS에서 홈페이지 유입, 행사 링크 유입, 실제 상담 연결이다. 현재 기준값이 없으므로 성과 증가율을 약속하지 않는다.

## 12. 첫 제작 단위

우선 실제 사례 자료를 확보하고 **콘셉트 비교 → 선정안의 메인 첫 화면 → 가장 설득력 있는 대표 사례의 연속 장면 → 다양한 업무·업종을 탐색하는 흐름 → 모바일**을 제작한다. 이 묶음의 품질 반복을 통과한 뒤 전체 페이지를 확장한다. SNS 사례 게시물 1종은 디자인 체계가 채널 밖에서도 성립하는지 확인하는 후속 시험으로 제작한다.

이 단계의 핵심 의사결정은 ‘얼마나 많은 효과를 넣을까’보다 ‘어떤 실제 작업을 회사의 첫인상으로 보여줄까’다.
